## 一、先明确你要学什么

这 30 天的重点不是训练模型，而是学习如何把大模型接入真实应用。

你要优先掌握的是：

- 如何调用模型 API
- 如何写清晰、可控的 Prompt
- 如何做结构化输出
- 如何实现文档问答 RAG
- 如何让模型调用工具
- 如何把 Demo 做成一个可展示的小项目

不建议一开始重度投入这些方向：

- 模型预训练原理
- 分布式训练
- 复杂数学推导
- 一上来就深挖框架源码

---

## 二、30 天后的达标标准

如果这份路线执行得比较完整，你应该能够做到：

- 独立调用至少一个大模型 API
- 做出聊天、摘要、信息抽取这三类基础功能
- 实现一个简单的文档问答系统
- 实现一个简单的 Tool Calling / Agent Demo
- 把项目整理成带 README 的可运行作品

---

## 三、整体学习顺序

建议严格按这个顺序推进：

1. Python 和 API 基础
2. Prompt 与原生 API 调用
3. 结构化输出与工程细节
4. RAG 文档问答
5. Tool Calling / Agent
6. 小型完整项目

原因很直接：先理解底层能力，再引入框架，排错和扩展都更稳。

## 七、学习中的常见误区

### 误区 1：一开始就学模型训练

对应用开发初学者来说，这不是优先级最高的内容。先学怎么把模型接进业务，再回头补训练与微调。

### 误区 2：一开始就重度依赖框架

如果没理解底层 API、消息结构、上下文传递和输出约束，后面很容易只会“拼组件”，不会排错。

### 误区 3：只看教程，不写代码

大模型应用开发非常依赖实践。只看视频，通常会停留在“看懂了”，做项目时还是会卡住。

### 误区 4：过于关注模型排名

入门阶段更重要的是流程跑通、结构清晰、工程稳定，而不是先追求“最强模型”。

### 误区 5：忽视成本和稳定性

很多 Demo 看起来能跑，但没有日志、重试、输出校验、成本控制，基本无法进入实际项目。
