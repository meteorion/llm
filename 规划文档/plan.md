> 2026 年，AI 大模型应用开发已告别"随便调 API 就能上岗"的野蛮生长期，全面转向**私有化知识库、Agent 流程自动化、多模态落地**等商业化刚需场景。

## 第一阶段：夯实基础与提示词工程（入门）

**目标**：建立对大模型的基本认知，掌握与 AI 交互的核心技能，能独立开发简单的 AI Demo。

**学习内容**
- **Python 编程速通**：变量、循环、函数、字典/列表、类、文件读写、异常处理、虚拟环境；异步编程（`asyncio`）与 API 请求；熟悉 Cursor / VS Code 等 AI 原生 IDE。
- **大模型基础概念**：Transformer 架构、Token、上下文窗口、Temperature/Top-p、Embedding，以及"幻觉"问题。核心认知是**"用好预训练模型"而非从零训练**。
- **原生 API 调用**：官方 SDK 优先；`system`/`user`/`assistant` 消息结构、多轮对话上下文、**流式输出（streaming）**。
- **提示词工程（Prompt Engineering）**：角色设定、目标拆解、思维链（CoT）、少样本（Few-shot）。
- **结构化输出（易被忽略但很关键）**：让模型稳定输出 JSON、字段约束、解析失败重试与兜底校验。

**阶段项目（三选做，建议全做）**
1. 命令行多轮聊天 Demo（维护上下文）
2. 文章摘要器（对比 ≥2 版 Prompt 的效果）
3. 结构化信息抽取工具（稳定输出可解析 JSON）

**通关标准**
- 能写一个稳定调用模型 API、支持多轮对话的程序
- 能让模型稳定输出结构化结果，并对异常输出不崩溃
- 有一套可复用的 Prompt 模板

## 第二阶段：核心应用架构 / RAG（进阶）

**目标**：深入理解企业落地大模型的主流架构，解决模型知识滞后和幻觉痛点。

**学习内容**
- **RAG 全流程**：文档加载 → 文本分割（Chunk 大小/重叠）→ 向量化 → 向量存储 → 语义检索 → 生成回答；掌握 LangChain / LlamaIndex 框架，以及 Chroma（轻量）、Milvus（生产）等向量库。
- **文档解析进阶**：PDF/表格/扫描件的解析与清洗（真实数据往往很脏，这一步决定上限）。
- **RAG 优化**：多路召回、混合检索（关键词 + 向量）、结果重排序（Reranker）、假设文档（HyDE）、查询改写。
- **评估体系（企业刚需）**：用 RAGAS 等评估召回率/忠实度/答案相关性；给回答加**引用来源**，确保可追溯。

**阶段项目**
- 一个最小可用的本地文档问答系统：支持读文档 → 检索 → 基于资料回答 → 附引用来源。

**通关标准**
- 能独立搭出一个带引用、只基于给定资料回答的 RAG 系统
- 能说清 Chunk 切分、检索质量、重排序分别如何影响最终答案
- 有一套量化评估 RAG 效果的方法，而非"看起来还行"

## 第三阶段：智能体与复杂工程化（高阶）

**目标**：赋予 AI 自主执行能力，并建立可上生产的工程化架构。

**学习内容**
- **Function Calling / 工具调用基础**：工具参数定义、模型何时触发工具、如何拿回结果——这是 Agent 的地基，务必先打牢。
- **Agent 开发**：思考-行动-观察（ReAct）循环、自主规划、记忆、工具调用；进而多 Agent 协同。
- **Agent 框架与协议**：LangGraph（有状态、可控的 Agent 编排）；**MCP（Model Context Protocol）**——2026 年连接模型与外部工具/数据源的事实标准，值得重点掌握。
- **大模型工程化架构**：模型网关（统一接口、路由、限流）、上下文工程（Context Engineering）、状态管理、反馈追踪。
- **可观测性与评估**：LangFuse / LangSmith 做链路追踪、日志、成本监控与离线评测。
- **成本与性能**：Prompt/结果缓存、批处理、模型分级路由（简单任务用小模型）。
- **安全**：Prompt 注入防护、越权与敏感信息泄露、输出内容护栏（guardrails）。

**阶段项目（三选一并做完整）**
- 本地文档问答助手 / 企业知识库客服助手 / 可调用工具的个人助理
- 要求：接入界面（Streamlit / Gradio）、带日志与配置、有异常处理与输出校验、跑通 ≥10 组测试用例。

**通关标准**
- 能做出一个会自主判断并调用工具、可观察、可复现的 Agent
- 项目具备工程可维护性：配置外置、日志、重试、成本可控
- 能识别并缓解基本的安全风险（如 Prompt 注入）

## 第四阶段：底层部署与模型定制（专家 · 按需）

**目标**：面向企业级高阶需求，掌握数据隐私、降本增效及深度定制能力。

> ⚠️ **取舍提醒**：对纯应用开发岗，本阶段优先级**低于**把二、三阶段的 RAG/Agent 做深。多数业务问题应先用"更好的 Prompt + RAG + 工具"解决，微调是最后手段。按实际岗位需求决定投入深度。

**学习内容**
- **私有化部署与量化**：开源模型本地环境搭建与服务封装（Ollama 快速起步、vLLM 高吞吐推理）；量化技术（INT8 / GGUF / GPTQ），在微小损失下大幅降低算力要求。
- **模型微调（Fine-Tuning）**：构建含正负样本的多样化数据集；LoRA / QLoRA 轻量化微调；用行业专有数据做适应性训练。先想清楚**"什么时候该微调、什么时候不该"**。
- **多模态技术拓展**：打通文本、图像、音频、视频；看图问答、语音对话等复合功能。
  - 💡 说明：视觉多模态（看图问答）在 2026 已很易上手，无需等到本阶段，第一/二阶段有余力即可提前尝试。

**通关标准**
- 能在本地/服务器上部署并封装一个量化后的开源模型服务
- 能独立构建数据集并用 LoRA 完成一次可评估的微调
- 能判断一个业务问题该用 Prompt / RAG / 微调中的哪种方案

## 贯穿全程的横向能力（不是某一阶段，而是一直练）

- **评估驱动**：任何改动都用可量化的指标验证，别靠"感觉变好了"
- **成本意识**：随手估算 Token 与请求成本，长输入/长输出的差异
- **安全与合规**：密钥管理、数据脱敏、注入防护
- **版本与实验管理**：Prompt、数据集、模型配置都要能回溯

## 学习建议与常见误区

**递进逻辑**（切忌颠倒顺序）：
基础代码 → 简易应用 → 框架编排 → 知识库落地 → 自主智能体 → 私有部署 → 模型定制。

**常见误区**
1. 一开始就学模型训练——先学怎么把模型接进业务，再回头补微调。
2. 一开始就重度依赖框架——不懂底层 API 和消息结构，后面只会"拼组件"不会排错。建议顺序：原生 API → Prompt → 结构化输出 → RAG → Tool Calling → LangChain/LangGraph。
3. 只看教程不写代码——大模型开发极度依赖实践，"看懂了"≠"会做"。
4. 过度关注模型排名——入门期流程跑通、结构清晰、工程稳定比"最强模型"更重要。
5. 忽视成本与稳定性——没有日志、重试、校验、成本控制的 Demo 进不了实际项目。

**每周复盘模板**
- 这周实际做出了什么可运行的东西？
- 哪个环节只是"看懂"，还没真正掌握？
- 哪个问题最浪费时间，根因是什么？
- 下周只做一件最重要的事，会是什么？

## 推荐技术栈（初学者简单路线）

- 语言：Python 3.10+
- SDK：官方 SDK 优先
- Web Demo：Streamlit 或 Gradio
- 向量库：先用轻量的 Chroma，再上 Milvus
- 框架：先原生 API，再逐步引入 LangChain / LangGraph / LlamaIndex
- 评估/观测：RAGAS、LangFuse / LangSmith
- 部署/微调（第四阶段）：Ollama、vLLM、LoRA/QLoRA
