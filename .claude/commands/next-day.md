# /next-day — 完成下一天的学习笔记梳理

完成下一天的学习笔记梳理任务，包括新建笔记文件、更新 README、补充面试题、同步路线图进度。

---

## 执行步骤

### Step 1：确定下一天的编号和主题

1. 读取 `README.md` 中的 `📒 学习笔记进度` 部分，找到最后一个 `[x]` 对应的 Day 编号 N。
2. 下一天为 Day N+1。
3. 读取 `规划文档/llm_app_30_day_roadmap.md`，定位 `### Day N+1` 小节，提取：
   - **主题名称**（标题中的描述）
   - **学习重点**（bullet 列表）
   - **当天任务**（bullet 列表）
   - **产出标准**（bullet 列表）

### Step 2：创建学习笔记文件

文件路径：`学习笔记/dayNN_<主题>.md`（主题用小写英文 + 下划线，参考已有文件命名风格）。

**笔记内容要求**：

- 参考最近几篇笔记的格式风格（如 day27、day28），而非早期的 day05
- 章节数量根据内容深度灵活调整，不必固定为七节
- 包含以下结构：

```
# Day N+1：<中文主题>

> 学习目标：<从路线图中提炼>
>
> 📚 所属阶段：**第X阶段 · <阶段名>**（见 [`plan.md`](../规划文档/plan.md)）｜ 配套：[30 天路线](../规划文档/llm_app_30_day_roadmap.md) · Day N+1
>
> 🧭 导航：[← Day N · <上一天主题>](dayN_*.md) → Day N+2 · <下一天主题>（待更新）

---

## 目录
（完整目录，每个 H2/H3 章节都列出）

---

## 一、<核心概念一>
各小节：1.1 / 1.2 / 1.3 ...
（每节包含原理解释 + ASCII 示意图或对比表格 + Python 代码示例）

## 二、<核心概念二>
...

## N、Day N+1 知识速查
快速参考表格、代码模板

## N+1、实践任务
- 任务清单（checkbox 格式）
- 产出标准

## N+2、下一步预告
Day N+2 的预告内容
```

**写作标准**：
- 每个概念都配 ASCII 示意图或对比表格，保持已有笔记的视觉风格
- 代码示例完整可运行，注释最少化（只在非显而易见的地方加注）
- 中文书写，技术术语保留英文
- 内容深度与已有笔记保持一致，不要写空洞的概述

**Markdown 格式规则（必须遵守）**：
- **严禁嵌套代码块**：不能在一个 ` ``` ` 块内再写 ` ```bash ` 或 ` ```python ` 等内层块，否则外层会被提前关闭，导致此后所有内容渲染错乱
- 需要展示"README 里应该怎么写"等示例时，用表格、缩进文本或分开的独立代码块，而不是 ` ```markdown ` 外层包内层
- 纯说明性文字（非代码、非 ASCII 图）用普通段落或列表，不要套进 ` ``` ` 块

### Step 3：更新 README.md（三处）

**更新一：`### 学习笔记` 表格**

在表格末尾添加新行：

```
| [`dayNN_topic.md`](学习笔记/dayNN_topic.md) | <主题> | <3-5 个关键内容点，逗号分隔> |
```

**更新二：`### [dayNN_topic.md]` 内容目录**

内容目录区域按**最新日在最前**的倒序排列。新条目插入位置：上一天（Day N）条目的**正上方**，不是文件末尾。

格式与其他 Day 一致：

```
### [dayNN_topic.md](学习笔记/dayNN_topic.md) — Day N+1：<中文主题>

- **一、<核心概念一>**
  - 1.1 <子节> / 1.2 <子节> / ...
- **二、<核心概念二>**
  - ...
- **N、Day N+1 知识速查**（关键点一览）
- **N+1、实践任务**（任务清单 + 产出标准）

---
```

**更新三：`📒 学习笔记进度`**

将最后一行 `- [ ] Day N+1 起 · 待更新` 替换为：

```
- [x] [Day N+1 · <任务描述>](学习笔记/dayNN_topic.md)
- [ ] Day N+2 起 · 待更新
```

### Step 4：更新面试题.md

**更新前先确认**：grep 或读取 `面试题.md` 末尾，找到当前最后一个 Q 编号 M，新题从 Q(M+1) 开始编号。

**更新一：文件头部说明**

将 `> 持续更新，当前覆盖 Day 1–N` 改为 `> 持续更新，当前覆盖 Day 1–(N+1)`

**更新二：目录**

目录区域同样按**最新日在最前**的倒序排列。新主题块插入到上一天主题块的**正上方**：

```
**<当天主题类别>**
- [Q(M+1). <问题>](#q(M+1))
- [Q(M+2). <问题>](#q(M+2))
...

**<上一天主题类别>**（已有，不动）
```

**更新三：题目内容**

在文件**末尾**追加新分类标题和题目完整内容（每题格式：`### Q编号` + 加粗问题 + 结构化答案）。

**题目数量**：不限定，根据当天主题知识点密度自行判断——每个值得单独考察的知识点出一题，直到主题被完整覆盖为止。不为凑数出重复题，也不因约束漏掉重要考点。

**题目质量要求**：
- 难度分层：基础概念 → 对比辨析 → 工程实践 → 综合应用，保持合理梯度
- 答案完整但简洁，使用表格或代码块呈现技术细节
- 最后一题必须是综合应用题（"如何设计…"或"从零实现…"）
- 避免与同主题类别内已有题目重复考点

### Step 5：更新路线图进度

在 `规划文档/llm_app_30_day_roadmap.md` 的 `当前进度` 部分，将最后一行 `- [ ] Day N+1 起 · 待完成（...）` 替换为：

```
- [x] Day N+1 · <任务描述> → [`dayNN_topic.md`](../学习笔记/dayNN_topic.md)
- [ ] Day N+2 起 · 待完成（继续按下方每日任务清单推进）
```

---

## 执行顺序

按 Step 1 → 2 → 3 → 4 → 5 顺序执行，每步完成后继续下一步，**不要中途停下来等待确认**。

所有文件写完后，简短汇报：
- 新建了哪个笔记文件
- README 哪三处更新了
- 面试题新增了哪些题号（Q几到Q几，共几题）
- 路线图是否同步

---

## 注意事项

- 如果 `$ARGUMENTS` 提供了具体的 Day 编号或主题，优先使用参数而不是自动推断
- 笔记内容要有实质深度，不要写空洞的目录占位符；如果某个实现细节还没有对应路线图内容，根据主题合理展开
- 代码示例使用 DeepSeek API（`base_url="https://api.deepseek.com/v1"`），与已有笔记保持一致
- 保持已有文件的 Markdown 格式风格（标题层级、表格对齐、代码块语言标注）
