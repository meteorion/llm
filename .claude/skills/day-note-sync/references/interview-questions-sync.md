# 面试题.md 同步规则

## 文件结构

```
# 大模型应用开发 · 面试题

> 持续更新，当前覆盖 Day 1–30（全部完成）+ Day 1–7 补充考点（Q156–Q174）

---

## 目录

**{分组标题，通常=某天或某主题}**
- [QN. {问题原文}](#qN)
- ...

...（所有分组）

---

## {Day 主题}          <- 与目录里的分组标题一一对应

### QN

**{问题原文，和目录里那一行的问题文字完全一致}**

{答案正文：表格/代码块/要点列表均可}

---

### Q{N+1}
...
```

顶部"目录"区块按分组罗列所有题目的锚点链接；正文区块按分组把每题的完整问答铺开。新增一天的题目，两处都要加。

## 插入位置

1. **目录区块**：在 `## 目录` 下已有分组列表的**末尾**（即最后一个 `**分组标题**` 块之后），新增一个 `**{Day 主题}**` 分组和它的题目链接列表。不要插进中间——目录分组顺序和正文分组顺序需要保持一致，都是"追加到末尾"。
2. **正文区块**：新分组标题 `## {Day 主题}` 追加在文件当前最后一个 `## ` 分组之后（用 `Grep -n "^## " 面试题.md` 找到当前最后一行 `##` 标题的位置，插在它之后、文件结尾之前）。若文件末尾有"补充考点"这类附录性分组（如现有的 `## Day 1–7 补充考点`），新分组插在附录之前，保持"按学习顺序排列、附录始终在最后"的约定。

## 编号规则

- 先用 `Grep -n "^### Q" 面试题.md` 找到当前最大的 Q 编号，新题从 `最大编号 + 1` 开始连续编号，不要跳号、不要复用已删除的编号。
- 每题标题格式固定为 `### Q{N}`（三级标题，不带问题文字；问题文字放在下面加粗的第一行）。

## 单题格式

```markdown
### Q{N}

**{完整问题，通常是"是什么/为什么/怎么做"三种句式之一，长度接近一句话}**

{答案。优先用以下结构之一：}
- 概念题：先给一句话定义，再给对比表或分点说明
- 原理题：给流程图式的文字步骤或代码示例
- 实践题：给一段可运行的代码 + 简短说明"为什么这样写"

**{可选：一行加粗的记忆点/易错点小结，很多现有题目结尾都有}**
```

答案详略参考同阶段已有题目（比如 Agent 相关题参考 `## Tool Calling 基础`、`## 多步工作流` 分组里的现有 Q），不要比现有题目薄很多或厚很多。

## 顶部说明行同步

第 3 行 `> 持续更新，当前覆盖 Day 1–30（全部完成）+ ...` 要跟着更新覆盖范围。深化阶段的题目不算"Day"编号延续（因为深化阶段的路线图不一定按"Day”编号推进），描述里按实际情况写清楚覆盖到了哪个阶段/哪些主题，例如：

```
> 持续更新，当前覆盖 Day 1–30（全部完成）+ Day 1–7 补充考点（Q156–Q174）+ 深化阶段·Agent 框架（QXXX–QYYY）
```

## 校验

写完后用 `Grep -n "^### Q" 面试题.md | tail -5` 和 `Grep -c "^### Q"` 类的检查确认：新题编号连续、总数和目录里链接数一致、没有重复的 `#qN` 锚点。
