# README.md 同步规则

README.md 里有三处和"新增一天笔记"相关的内容，都要同步，否则 README 和实际笔记会脱节。

## 1. 顶部"学习笔记"表格

在"### 学习笔记"标题下的表格里，按 Day 顺序追加一行（表格已按 Day 1→30 顺序排列，新行加在最后一个已有行之后）：

```markdown
| [`dayNN_{slug}.md`](学习笔记/dayNN_{slug}.md) | {笔记标题去掉"Day N："前缀} | {3-5 个用、隔开的关键内容短语，概括笔记里最重要的知识点/产出} |
```

"关键内容"列参考已有行的写法：不是完整句子，是用"、"分隔的名词短语（如"README 5 分钟测试标准、项目介绍/运行步骤/示例写法、完整 README 模板"），挑笔记里最值得被检索到的 3-5 个关键词/概念。

## 2. "📋 各文件内容目录"区块

这个区块给每个笔记文件生成一份"章节大纲"，格式：

```markdown
### [dayNN_{slug}.md](学习笔记/dayNN_{slug}.md) — Day {N}：{主题}

- **{一级章节标题}**
  - {二级小节标题}（{括号里补一句这个小节讲的核心结论/对比，不是重复标题文字}）
  - ...
- **{下一个一级章节标题}**
  - ...
```

直接把新笔记"目录"区块的结构搬过来，去掉数字编号前缀（"一、""1.1"这些不要），每个二级小节后面用括号补一句"这一节的干货是什么"（不是简单复述标题）。新增的这一整块追加在"📋 各文件内容目录"区块里上一个 Day 的小节之后。

## 3. 底部"当前进度"复选清单

README 里单独维护了一份和 `llm_app_30_day_roadmap.md`（或深化阶段路线图）里"当前进度"清单**内容相同但物理上独立**的清单（搜索 `- [x] [Day` 定位）。新增一行并勾选：

```markdown
- [x] [Day {N} · {主题}](学习笔记/dayNN_{slug}.md)
```

如果这行是所属阶段/全程的最后一天，其后原有的"🎉 xx 学习完成！"提示行要跟着挪到新的最后一行之后（如果还没到最后一天，不用管这行）。

## 易错点

- 三处的"主题"文案要和笔记 H1 标题、路线图里的 Day 描述三者一致，不要三处各写一套说法。
- 表格行和大纲小节都是"只追加、不重排"——除非用户明确要求重新整理 README 结构，否则不要顺手改动已有行的措辞。
