# 学习笔记模板

以 `学习笔记/dayNN_<slug>.md` 为路径。下面是常规日（非复盘日）的完整结构，`{}` 内为需要替换的占位符。

## 头部

```markdown
# Day {N}：{主题}

> 学习目标：{一句话说明这天要掌握什么能力，动词开头，如"掌握 XX 原理，实现 YY，理解 ZZ 的取舍"}
>
> 📚 所属阶段：**{阶段名，如"第三阶段 · 智能体与工程化"}**（见 [`plan.md`](../规划文档/plan.md)）｜ 配套：[{路线图显示名，如 "30 天路线" 或 "深化阶段路线"}](../规划文档/{roadmap_file}.md) · Day {N}
>
> 🧭 导航：[← Day {N-1} · {上一天主题}](day{N-1}_{上一天slug}.md) → Day {N+1} · {下一天主题}{若下一天笔记还没写则加"（待更新）"，已写则直接给真实文件链接}

---
```

- 若这是所属阶段的第一天，导航行没有"←"部分，只有"→"。
- 若这是所属阶段/全程最后一天，导航行没有"→"部分，改成加粗的阶段性收尾提示（参考 `day30_project_summary.md` 第 7 行："**30 天学习结束 🎉**"）。

## 目录

用中文数字一级编号（一、二、三…）对应正文的 `##` 一级章节，二级编号（1.1、1.2…）对应 `###` 小节。锚点规则：中文标题去标点后用短横线连接（GitHub 风格），例如 `## 一、参数设计原则` 对应锚点 `#一参数设计原则`。目录本身不编号最后两节前的分隔线。

标准收尾三节（几乎每篇都有，编号紧接正文最后一个知识章节）：
- `## {N}. Day {N} 知识速查`：一张或多张表格，横向对比当天核心概念/API/参数，供复习时扫一眼回忆全部要点，不要重复正文的完整解释。
- `## {N+1}. 实践任务`：`- [ ]` 任务清单 3-6 条，每条是具体可执行的操作（跑一个脚本、改一处配置、做一次对比实验），不要写"理解 XX"这种无法验证是否完成的任务。清单后跟一段**产出标准**，用 1-3 条说清楚"做到什么程度算通过"。
- `## {N+2}. 下一步预告`：2-4 句话说下一天要学什么、和今天的关系是什么、今天做的哪个决定会被下一天用到。如果是阶段/全程最后一天，这一节替换成总结与结束语（见下方"最后一天"）。

## 正文写法要求

- 每个 `##` 一级章节 2-4 个 `###` 小节，避免只有一个小节的"一级章节"（信息量不够独立成一级标题的，合并进上一节）。
- 概念解释配一张对比表或一段代码示例，不要只有纯文字段落；表格优先用于"A vs B"或"多个选项对比"场景，代码优先用于"这是怎么实现的"场景。
- 出现"❌ 差的写法 / ✅ 好的写法"这种对比时统一用这两个符号，和已有笔记（如 `day30_project_summary.md` 第二节）保持一致。
- 代码块标注语言（` ```python `、` ```bash `），示例代码要能独立看懂，不依赖笔记里没展示过的变量。

## 最后一天（阶段收尾 / 全程收尾）

参考 `day30_project_summary.md` 的第六、七、九节结构：
- 一节"{N}. 天数学习总结"：按阶段梳理核心产出 + 核心技能。
- 一节"认知转变"或"知识地图"：3-5 条"起点 → 终点"式的认知升级描述。
- 一节"下一步去哪里"：给出 2-3 条候选路线（不是单一路线），并说明选路线的判断标准；如果已经有更细的下阶段路线图文件，在这里直接链接过去。
- 最后一节口语化的结束语，不用目录编号，标题类似"## 九、{阶段名}学习结束语"。

**这类笔记写完之后不会再被改动**：即使后续新开一个阶段并写出了 Day {N+1}，也不要回头把这篇笔记头部导航行的收尾语（如"— **30 天学习结束 🎉**"）改写成指向 Day {N+1} 的常规链接。等真的开始写下一阶段第一天的笔记时，只在这篇笔记"下一步去哪里"一节里追加一条链接指向新笔记/新路线图，导航行保持原样——收尾语是这篇笔记的一部分设计，不是"占位符待补"。

## 复盘日（Day 7 / 14 / 21 等）的结构差异

复盘日不是"学新知识"，笔记以问答和横向总结为主：
- 目录里没有"实践任务"表格式清单，改成"复盘问题"小节：列 3 条左右的自问自答（问题 + 答案），对应路线图里当天的"复盘问题"。
- 一定有一节"本周 N 个 Demo/产出横向对比"或"知识地图"表格，把这周每天的产出穿成一条线。
- 产出标准通常是"整理出一份可复用的模板/骨架代码"，比常规日更偏"沉淀"而非"新增功能"。
