# Day Note Sync

为本仓库新增一天学习笔记时，同步完成四件事：写笔记、追加面试题、勾选路线图进度、同步 README。这四步始终按顺序整套执行，不单独只做一步——除非用户明确只要求其中一步。

## 触发前先确认输入

开始前确认拿到：Day 编号、主题名（用于文件名 slug，如 `day31_langgraph_state_graph.md`）、以及这天要覆盖的知识点列表（若用户没给，先向用户要一份要点清单，不要凭空编造技术细节）。

判断这天属于哪个路线图文件：
- Day ≤ 30 → `规划文档/llm_app_30_day_roadmap.md`
- Day ≥ 31 → 先用 Glob 匹配 `规划文档/day31_*_deepening_roadmap.md` 找到当前的深化阶段路线图文件。文件名里的数字区间会随内容增补而变化（这份路线图目前已经改过好几次名字），不要在 skill 里硬编码具体文件名；若 Glob 匹配到多个文件，以文件顶部"当前进度"清单里区间覆盖到当前 Day 的那个为准，并提醒用户是否要清理掉旧文件

## 第一步：写学习笔记

在 `学习笔记/` 下创建 `dayNN_<topic_slug>.md`（两位数字，命名沿用已有笔记的英文 slug 风格）。

完整结构模板、每个区块的写法要求（导航行怎么写、目录锚点怎么生成、知识速查表怎么排、实践任务怎么写产出标准）见 `references/note-template.md`。写之前先读一篇同阶段最相近的现有笔记（如深化 Agent 方向可参考 `day25_multi_step_workflow.md`）对齐语气和详细程度。

周复盘型的 Day（对应路线图里"复盘"字样的日期）结构略有不同，同样在 `references/note-template.md` 里有单独说明。

写完后：
1. 在笔记正文最后一节前，若该 Day 不是所属阶段的最后一天，加"下一步预告"小节；若是最后一天，改成阶段性总结/结束语（仿照 `day30_project_summary.md` 第九节的写法）。
2. 更新前一天笔记顶部导航行的"→"部分（把"（待更新）"或指向占位符替换成指向新笔记的真实链接），后一天笔记（如果已存在）导航行的"←"部分同理更新。**例外**：如果前一天笔记是某个路线图的收尾笔记（导航行写的是"学习结束"这类庆祝性收尾语而不是指向下一天，例如 `day30_project_summary.md` 的"— **30 天学习结束 🎉**"），不要改动它的导航行——那是故意设计的仪式性收尾，不是待补链接。改成在它的"下一步去哪里"一节里追加一条指向新路线图/新笔记的链接（参考 `day30_project_summary.md` 6.3 节实际的处理方式：只在正文里加了一句链接，导航行原样保留）。

## 第二步：追加面试题

在 `面试题.md` 里为这一天新增一个 `## <Day 主题>` 小节，包含若干 `### QN`（N 从文件当前最大编号 +1 连续编号），并同步更新顶部目录与覆盖范围说明。

题量参考：内容较薄的一天出 3-5 题，信息量大的一天（如整合型/复盘型）出 6-10 题。题目要考读者对当天核心概念的理解，不要照抄笔记标题。

具体的插入位置、编号规则、目录分组写法、单题的问答格式模板，见 `references/interview-questions-sync.md`。

## 第三步：勾选路线图进度

在第一步判断出的路线图文件里，把这个 Day 对应的进度项从未完成状态改成已完成并加上笔记链接。若该路线图文件里还没有这个 Day 的条目（比如深化阶段路线图是新建的、还没有进度清单），先按已有条目的格式补一行再勾选。

## 第四步：同步 README

`README.md` 里有三处需要同步，具体格式模板见 `references/readme-sync.md`：
1. 顶部"学习笔记"表格新增一行（文件名链接 / 主题 / 关键内容概括）
2. "📋 各文件内容目录"区块新增该 Day 的大纲小节（复用笔记目录的一级/二级标题，去掉序号数字，只保留关键词）
3. 底部"当前进度"复选清单同步勾选该 Day

## 完成后自检

- 四个文件（新笔记 + 面试题.md + 对应路线图 + README.md）都改了，且改动前后 Day 编号、文件名、链接路径三者一致
- 面试题.md 的题号连续无跳号无重复
- 没有把还没写的未来 Day 提前标记为完成
- 不要主动执行 git commit / push——只改文件，交给用户自己决定何时提交（除非用户在这次请求里明确要求顺带提交）
